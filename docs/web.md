# MarginCast 웹사이트

`web/`은 매장 운영자가 POS 데이터와 메뉴 원가를 기준으로 전략을 검토하는 브라우저 화면이다.
별도 프론트엔드 프레임워크 없이 HTML, CSS, JavaScript로 구성하며 `src.http_api`가 정적 파일,
매장 설정 API(`/api/store/*`), 계산 API와 `POST /api/agent/chat`을 함께 제공한다.

## 화면 구성

| 탭 | 내용 |
|---|---|
| 대시보드 | POS 연동 상태, 최근 동기화, 주문·메뉴 수, 분석 가능 메뉴 수, synthetic 데이터 데모 고지, 수수료(읽기 전용), 위치 준비 상태 |
| 메뉴 관리 | POS 메뉴 목록, 식재료 원가 수정, 원가율·단품 기여이익 자동 계산, 분석 상태, 메뉴 추가 |
| 전략 시뮬레이션 | 가격·할인 비교, 주메뉴·구성 메뉴를 고르는 세트 비교 |
| AI 상담 | 기존 Agent Chat UI (`POST /api/agent/chat`) |

`#menus`, `#strategy`처럼 해시로 탭을 바로 열 수 있다. 메뉴 관리에서 `분석 가능`인 메뉴의
`전략 보기`를 누르면 그 메뉴가 선택된 전략 시뮬레이션으로 이동한다.

### 메뉴와 원가

- 원가율은 입력값이 아니라 `식재료 원가 / 판매가`로 계산한다. 단품 기여이익은 엔진과 같은 식
  `판매가 - 식재료 원가 - 수수료(매장·배달 판매 비중 반영)`이다.
- POS 메뉴의 판매가는 POS 값이라 수정하지 않는다. 식재료 원가는 수정할 수 있으며, 수정한 값은
  `USER` 원가로 저장돼 가격·할인·세트 시뮬레이션의 기여이익과 Agent 가격 계산에 모두 반영된다.
  수요 예측과 가격탄력성은 원가를 사용하지 않으므로 바뀌지 않는다. 결과 카드에는 사용한 원가와
  출처를 `직접 수정한 원가` 또는 `POS 기준 원가`로 표시한다(내부 값 `USER`·`POS_HISTORY`는 화면에 노출하지 않는다).
- 포장비 입력과 요청별 수수료율 설정은 계산 엔진이 모델링하지 않아 화면에서 제공하지 않는다.
  수수료는 `현재 엔진 적용값 · 읽기 전용`으로만 보여준다.
- 새 메뉴는 메뉴명·카테고리·판매가·식재료 원가·판매 채널만 입력한다. 판매·가격 변경 이력이 없어
  `데이터 수집 중`으로 표시하며 가격탄력성, 성공확률, 시뮬레이션을 만들지 않는다.
- 분석 상태는 엔진 capabilities에서 가져온다: `분석 가능`, `가격 변화 데이터 부족`, `데이터 수집 중`.

### 전략 시뮬레이션

일반 화면에는 메뉴, 변경 가격 또는 할인, 분석 기간, 세트 가격과 구성 메뉴만 있다.
Monte Carlo 반복 횟수와 seed는 엔진 `execution_defaults`를 그대로 사용하고, 내부 메뉴 ID,
모델 파라미터는 `?debug=1`에서만 보인다.

세트는 POS 메뉴 목록에서 주메뉴(MAIN)와 구성 메뉴(1~4개)를 고른다. 먼저 POS에서 관측한
기간, 주메뉴 판매량·주문 수, 함께 구매된 횟수와 기존 동시구매율을 보여주고, 판매 데이터만으로
알 수 없는 네 가지 비율은 그렇다고 표시한다. `계획 시나리오로 비교`는 엔진이 내려주는 보수·기준·
낙관 계획값(출처 `DEFAULT`)으로, `고급 가정 직접 입력`은 사용자가 네 값을 모두 입력한 경우에만
(출처 `USER`) 계산한다. 화면과 LLM은 임의 숫자를 채우지 않는다. 계획값은 화면에서 `계획용 가정`으로
표시하고 "계획용 가정이며 실제 POS 데이터에서 추정된 값이 아닙니다" 문구를 결과 위에 항상 둔다.
네 비율의 실제 수치는 `고급 가정 직접 입력`을 펼쳤을 때만 참고용 표로 보인다.
좁은 화면(1100px 이하)에서는 세트 결과 표, 900px 이하에서는 메뉴 표를 카드 형태로 바꾼다.

### 매장 위치

위치 기능은 이번 단계에서 연결하지 않았다(상태·문구 제안은 [위치·날씨 UI 구조 제안](location-ux-proposal.md)).
대시보드에 `위치 기능 준비 중` 상태만 표시하며,
`현재 위치 사용`·`매장 검색`은 다음 단계에서 연결한다. 그 전까지 가격 분석은 최근 관측 날씨를
사용한다.

## 실행

```powershell
ollama serve
ollama pull qwen3:1.7b
$env:OLLAMA_BASE_URL="http://localhost:11434"
$env:OLLAMA_MODEL="qwen3:1.7b"
.\.venv\Scripts\python.exe -m src.http_api
```

브라우저에서 `http://127.0.0.1:8000`에 접속한다. 실제 데모 전에 가격 질문을 한 번 보내 모델을
warm 상태로 준비한다. 서버 startup에서는 모델이나 사업 Tool을 자동 호출하지 않는다.

OpenAI 배포 설정과 Provider 선택은 [LLM Provider와 배포 준비](providers-and-deployment.md)를
참고한다. 두 Provider 모두 같은 HTTP 응답과 화면을 사용한다.
## AI 상담 화면 흐름

1. 메뉴와 변경 가격을 자연어로 입력한다.
2. 가격이 빠지면 `NEEDS_INPUT` 질문을 일반 Agent 메시지로 받고 같은 세션에서 답한다.
3. 요청 중에는 실제 backend progress가 아닌 대기 안내 문구를 단계적으로 표시한다.
4. `COMPLETED`이면 설명과 다음 행동은 `presentation`에서, 계산 숫자는 `facts`에서 각각 표시한다.
5. Decision Engine의 `추천`, `소규모 실험`, `보류` 판단을 결과 카드의 최상단에 표시한다.
6. 기여이익 변화, 개선확률, 예상 범위, 하방 위험, 근거 품질과 데이터 고지를 확인한다.

`REJECTED`는 내부 위반 코드를 숨기고 수동 재시도 버튼을 제공한다. `ERROR`도 내부 예외와
stack trace를 표시하지 않으며 같은 재시도 버튼을 제공한다. 새 대화는 브라우저 메모리의 현재 `session_id`와 메시지를 초기화한다.

## 계산값과 설명의 경계

결과 카드 숫자는 `facts`만 사용한다. `presentation.explanation`이나 `presentation.next_action`에서
숫자를 파싱하지 않는다. 각 fact의 `source`와 `source_ref`는 기본 화면에서 숨기며, 필요하면
API 응답에서 확인한다. `?debug=1`에서는 민감하지 않은 `execution_id`와 `recommendation_id`만
추가로 표시하며, 정적 안전 설명이 사용됐는지 확인할 수 있도록 `presentation_source`도 표시한다.

합성 데이터 warning과 근거 품질 고지는 결과 카드 하단의 `데이터와 가정` 영역에 표시한다.
페이지 footer에도 프로토타입이 실제 매장 성과를 보증하지 않는다는 고정 고지를 둔다.

H1 날씨 가격 요청은 위치가 없을 때 현재 위치와 매장 위치 검색 버튼을 표시한다. 현재 위치는
Browser Geolocation API로 얻어 한 요청에만 넣고, 권한이 거절되면 주소 검색 입력을 연다. 주소
검색 원문도 요청 뒤 화면 상태에 보존하지 않는다. 완료 카드에는 ENGINE facts의 실제 예보 반영
여부와 적용 날짜만 표시하고 위경도나 KMA 격자는 숨긴다.

## 브라우저 경계

웹사이트 JavaScript에는 API key, System Prompt, ToolResult 원문을 넣거나 표시하지 않는다.
서버가 `ERROR`를 반환하거나 네트워크 요청이 실패해도 브라우저에는 정해진 일반 안내만 표시한다.
대화 중에는 서버가 반환한 같은 `session_id`를 후속 요청에 사용한다.

## 프론트 테스트

채팅 세션과 상태 전이는 외부 의존성 없는 `chat-core.js`에, 매장·메뉴·전략 화면의 순수 로직은
`store-model.js`에 두었다. `tests/test_store_model.js`는 원가율 재계산, 요청 조립, 화면 숨김 규칙,
세트 메뉴 하드코딩 제거를 검사한다.

```powershell
node --test tests/test_web_chat.js tests/test_store_model.js
```

## 현재 한계

- 합성 데이터로 학습한 데모 계산 결과다.
- 현재 Agent UI는 검증된 가격 질문 흐름만 지원한다.
- 로그인, 브라우저 새로고침 뒤 세션 복원과 장기 대화 저장은 포함하지 않았다.
- HTTP 서버는 해커톤 MVP의 단일 프로세스·단일 worker 전제다.
- 날씨, 세트 구성과 실험 피드백 Agent UI는 후속 범위다.
- 매장 설정(원가 수정, 추가 메뉴)은 서버의 로컬 JSON(`data/store/store_profile.json`)에 저장하며
  단일 매장·단일 프로세스 전제다. 이 파일은 Git에 포함하지 않는다.
- 실험 피드백 웹 화면은 채팅 UI로 대체되면서 제거된 상태이며, 이번 단계에서 복원하지 않았다.
- 세트 결과의 절대 기여이익(`scenario_contribution_profit`)은 과거 실현 이익 분포를 바탕으로 하므로
  수정한 원가는 변화량(`profit_delta`)에만 반영된다. 화면은 변화량을 중심으로 보여준다.
