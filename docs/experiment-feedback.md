# 실험 피드백과 모델 보정 근거

MarginCast는 추천 전략을 실행하기 전에 예측 분포를 실험 계획으로 저장하고, 실험 종료 뒤
같은 계획에 실제 결과를 연결한다. 이 순서를 지켜야 나중에 다시 계산된 값이 당시 예측을
대체하지 않는다. 기록은 예측 오차와 구간 보정 상태를 확인하기 위한 근거이며, 한두 건의
결과로 모델 계수를 자동 변경하지 않는다.

## 저장하는 값

- 실행 전에 저장하는 실험 이름, 메뉴, 시작일·종료일
- 정가·할인액과 예측 기간
- 판매량·기여이익·기여이익 변화의 예측 평균과 80% 범위
- 종료 뒤 연결하는 실제 판매량과 기여이익
- 실제 개선폭을 계산할 기준 기간 또는 병행 대조군의 기여이익과 산정 방식
- 당시 Decision Engine과 근거 품질 산식 버전·정책 지문
- 합성/실제 데이터 출처와 날씨 문맥
- 당시 근거 품질 점수·등급·검증 상태와 실행 판단

실제 기간의 날짜 수와 예측 기간이 다르면 비교를 거부한다. 예측 평균이 80% 범위 안에
있어야 하며 NaN과 무한대는 저장하지 않는다. 기본 저장 위치는
`data/feedback/experiment_feedback.json`이고 생성 데이터와 마찬가지로 Git에서 제외된다.

## 평가 지표

각 기록은 판매량·기여이익·기여이익 변화에 대해 다음을 계산한다.

- 예측 오차와 절대 오차
- 실제 값이 0이 아닐 때의 절대 비율 오차
- 실제 값의 80% 예측 구간 포함 여부
- 이익 개선 방향의 예측 일치 여부

집계에서는 평균 오차, 평균 절대 오차, 평균 절대 비율 오차, 80% 구간 포함률과 이익 방향
정확도를 확인한다. 충분한 실험이 쌓였다면 80% 구간 포함률이 실제로 약 80%인지 보고,
일관된 편향이 있을 때 수요 분산이나 탄력성·원가 가정을 다시 추정한다.

근거 품질 버전·등급별로 기여이익 변화의 평균 절대 오차, 80% 구간 포함률과 방향 정확도도
별도 집계한다. 이를 통해 높은 근거 품질이 실제로 더 정확한 예측과 연결되는지 검증한다.
실제 실험 수가 적을 때는 등급 간 차이를 확정하지 않는다.

집계 그룹은 `version`, `formula_fingerprint`, `label`을 함께 사용한다. 새 산식이 도입돼도 과거
점수와 등급을 다시 계산해 덮어쓰지 않으며, 서로 다른 버전이나 지문의 `MEDIUM`을 같은 집단으로
합치지 않는다.

집계 코드는 mock 실험 1건의 정상 사례와 실패 사례를 각각 검증한다. 실패 사례는 실제값이
80% 구간 밖에 있고 예측과 실제 이익 방향이 반대일 때 포함률과 방향 정확도가 모두 0이 되는지
확인한다. 별도의 2건 혼합 사례로 두 지표가 0.5가 되는 집계도 검증한다. 이 테스트는 파이프라인의
계산과 이상 신호 감지를 확인하지만, 실제 매장에 대한 예측 타당성을 입증하지는 않는다.

`matched_period`는 과거의 비슷한 기간과 비교하므로 날씨·요일·추세 교란이 남는다.
가능하면 `parallel_control`을 사용하고, 어느 방식도 한 건의 결과를 인과효과의 확정값으로
취급하지 않는다.

## 웹과 HTTP API

가격·할인 계산 뒤 `실험 피드백` 탭에서 예측 스냅샷과 기간을 계획으로 저장한다. 실험이
끝나면 같은 탭의 대기 중인 계획을 선택하고 실제 판매량·기여이익·기준선 기여이익을 입력한다.

| 메서드 | 경로 | 설명 |
|---|---|---|
| `POST` | `/api/experiments/plans` | 실행 전 예측 스냅샷 저장 |
| `GET` | `/api/experiments/plans` | 실제 결과를 기다리는 계획 조회 |
| `POST` | `/api/experiments/feedback` | 계획 ID에 실제 결과 연결 |
| `GET` | `/api/experiments/feedback/summary` | 완료된 실험의 누적 보정 지표 조회 |
