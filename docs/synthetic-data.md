# Synthetic POS Dataset 설계와 검증

## 범위와 실행

가상의 음식점 1곳, 8개 메뉴, 180일 운영을 생성한다. v2는 반복 가격·할인 실험과
다중 메뉴 가격 실험, 세트 전환 분해 Ground Truth를 포함한다.

```powershell
.\.venv\Scripts\python.exe -m src.generate_data --seed 42
.\.venv\Scripts\python.exe -m src.validate_data --check-reproducibility
.\.venv\Scripts\python.exe -m unittest discover -s tests -v
```

생성은 기존 동일 이름의 데이터 파일을 갱신한다. 생성 후 검증을 다시 실행해야
`validation_report.json`이 현재 데이터에 대응한다.
같은 코드·seed·시작일·Python 환경에서 재현하며, Python 버전이 다른 환경의 바이트 일치는 보장하지 않는다.
검증 보고서의 SHA-256은 CSV 8개와 Ground Truth JSON의 재생성 결과를 비교한 값이다.

## 데이터 사전

기본 기간: 2026-01-05~2026-07-03. Day 1은 시작일이며 이벤트 시작/종료일을 모두 포함한다.
시간은 매장 현지 시각(한국)이며, 타임존 오프셋 없는 ISO 형식으로 저장한다.
금액은 정수 원 단위이고 수량은 개수다. CSV는 Excel 한글 표시를 위한 UTF-8 BOM을 사용한다.

`daily_context.csv`는 추가한 관측 맥락 표다. 판매가 0인 메뉴·시간 셀을 EDA에서 복원하고,
주문이 없는 경우에도 영업 여부와 당일 날씨를 알 수 있도록 한다. 원가 이력은 주문일 이하의
가장 최근 `effective_date`를 적용한다. 초기 정가는 `menus.csv`, 가격 변경은 `experiments.csv`에 있다.

`experiments.value`의 의미는 PRICE=변경 정가, DISCOUNT=단위당 할인액, BUNDLE=세트 가격이다.
세트는 별도 메뉴를 추가하지 않고 기존 메뉴 2개의 상품 행에 같은 `bundle_id`를 부여한다.
추가 사이드의 `bundle_id`는 비어 있으므로 주문 총액은 세트 가격보다 클 수 있다.

## 수요 생성 원리

주문당 주메뉴는 1개이며 치킨마요·돈까스덮밥·제육덮밥·카레의 기본 일수요는 각각 44·42·38·32다.
사이드와 음료는 주메뉴에 부가 구매되며, 별도 단독 주문은 생성하지 않는다.

```text
셀 = 날짜 × 시간 × 채널 × 주메뉴
lambda = base_demand × weekday_factor × normalized_hour_weight
         × weather_factor × channel_share × daily_noise × late_growth
         × (paid_unit_price / base_price)^elasticity × promotion_factor
Q ~ Poisson(lambda)
```

요일 계수는 월~일 순서로 0.94, 0.96, 0.98, 1.00, 1.08, 1.18, 1.12다.
영업시간은 11:00 이상 22:00 미만이며, 정규화한 시간 가중치로 점심/저녁 피크를 만든다.
비 확률은 일별 28%, 비 오는 날 전체 수요 배수는 0.98이다.
배달 비중은 맑음 43%, 비 72%이며, STORE와 DELIVERY 비중의 합은 1이다.

일별 잡음은 `lognormal(mu=-0.04²/2, sigma=0.04)`로 평균이 1이다.
여기에 조건부 Poisson 표본 변동을 추가한다. 180일 규모에서 복잡한 분산 추정 없이
셀별 카운트와 일별 공통 흔들림을 구분하기 위해 선택했다.
이는 독립 Poisson만 사용한 생성도, Negative Binomial 모델 자체도 아니다.

날씨·수요·장바구니·세트 단계에는 SHA-256으로 파생한 독립 난수 스트림을 사용한다.
세트 활성 여부를 바꾸어도 실험 밖 거래 금액과 맥락은 유지된다. 시각순 ID를 다시 부여하므로
신규 주문 이후의 ID 자체는 달라질 수 있다.

## 원가와 기여이익

치킨마요 원가는 3,800→4,100(Day 90)→4,900원(Day 141)이다.
Day 141에 다른 식재료 메뉴의 원가도 20% 상승하며 음료 원가는 유지한다.
Day 142부터 기본 수요가 6% 증가한다. 매장 전체 기여이익 악화 데모를 위해
여러 식재료의 공급가 충격을 명시적으로 설정했다. 이는 실제 매장의 원가 추정치가 아니다.
원가가 수요에 직접 영향을 주는 경로는 없으며 Day 142의 수요 증가와 독립적인 사건이다.

```text
gross_sales = list_price × quantity
net_sales = gross_sales - discount_amount
contribution_profit = net_sales - ingredient_cost - platform_fee
                      - payment_fee - additional_promotion_cost
```

STORE: 플랫폼 0%, 결제 2%. DELIVERY: 플랫폼 15%, 결제 3%.
수수료는 할인 후 매출 기준, 상품 행마다 Python `round`로 원 단위 반올림한다(정확한 절반은 짝수).
주문 수수료는 행별 수수료의 합이다. 실제 결제 사업자의 청구/절사 규칙을 재현한 것은 아니다.
할인액은 실결제 금액에 반영돼 있으므로 기여이익에서 다시 빼지 않는다.
`additional_promotion_cost`는 별도 광고/행사비 용도이며 이번 데이터에서는 0이다.
고정비, 부가세 정산, 포장비, 배달 대행료, 취소·환불은 모델링하지 않는다.

## 세트 전환과 잠식

실험 전에 일반 장바구니를 만든 뒤 기존 고객의 장바구니를 교체한다.

| 유형 | 생성 규칙 | seed 42 결과 |
|---|---|---:|
| chicken_only | 기존 치킨마요 구매자 중 콜라가 없는 경우 35% 전환 | 180 |
| copurchase | 기존 치킨마요+콜라 구매자 중 65% 전환 | 128 |
| other_main | 다른 주메뉴 고객의 2.5%가 치킨마요로 교체 | 54 |
| incremental | 일별 기존 치킨마요 주문 수 × 0.12를 평균으로 한 Poisson 신규 주문 | 95 |

`chicken_only`는 다른 사이드까지 전혀 없다는 뜻이 아니라 **콜라 없는 치킨마요 장바구니**다.
기존 사이드/음료는 유지하고 필요한 콜라만 추가한다. 신규 세트 고객은 구성품 2개만 주문한다.
전환율은 추정치가 아닌 생성 가정이며 다른 세트 가격에서의 반응까지 모델링하지 않는다.
전환 출처와 교체 전 메뉴는 POS에서 관측할 수 없으므로 Ground Truth에만 기록한다.

정가 합계 11,000원에서 할인 1,000원을 치킨마요 818원·콜라 182원으로 나눠
구성품 실결제 금액 합계를 정확히 10,000원으로 맞춘다.

세트 457건 중 신규는 95건(20.79%)이고 기존 주문 전환은 362건이다.
동일 고객 수요의 세트 미실시 대조에서는 2,315건, 실시에서는 2,410건이다.
기존 주문 전환으로 M06 232개가 추가되고 다른 주메뉴 54개가 M01로 교체된다.
교체된 주메뉴는 M02 22개, M03 14개, M04 18개다.
신규 세트는 M01·M06을 각각 95개 추가한다. 같은 대조 대비 매출은 1,041,000원,
기여이익은 211,820원 증가했다. 이 분해는 `bundle_audit`에 별도 필드로 저장된다.
검증기는 전환된 주문을 원래 메뉴로 되돌렸을 때 메뉴별 수량까지 대조와 일치하는지 검사한다.

## 관측 결과와 가상 대조를 구분하는 이유

가격 구간 전후의 평균에는 날씨·요일·일별 잡음 차이가 섞인다.
관측 구간은 모두 7일이라 요일 구성은 같지만 날씨와 표본 잡음까지 같지는 않다.
그래서 같은 셀의 균등 난수에 서로 다른 Poisson 평균을 적용한 가상 대조 수요를 함께 저장한다.
가격과 프로모션만 제외한 대조이며, 현실에서 관측 가능한 통제집단은 아니다.
이 결합에서는 평균이 줄면 대조보다 카운트가 늘지 않도록 표본을 짝짓는다.
실제 두 기간의 판매량 방향이 모든 seed에서 항상 같도록 결과를 재추첨하지 않는다.

| 실험 | 동일 조건 가상 대조 대비 수량 변화 |
|---|---:|
| M01 1,000원 할인 3회 | +37.66%, +38.99%, +37.28% |
| M01 9,500원 2회 | -4.44%, -6.69% |
| M01 10,000원 2회 | -13.84%, -10.03% |
| M02 1,000원 할인 2회 | +24.26%, +23.13% |
| M02 10,500원 2회 | -4.30%, -6.35% |
| M02 11,000원 | -9.67% |
| M03 10,000원·10,500원 | -5.67%, -12.17% |

모든 할인 실험에서 무개입 수요 < 가격 효과만 적용한 수요 < 프로모션 노출까지 적용한 수요의
순서가 확인됐다. 이는 생성 규칙의 검증이며 현실의 인과효과를 검증한 결과는 아니다.

추가 관측 결과(seed 42):

- 하루·시간당 주문: 점심 24.52건, 저녁 21.82건, 14~16시 6.62건.
- 일평균 주문: 평일 156.97건, 주말 182.12건.
- 배달 비중: 맑음 43.00%, 비 72.39%.
- 원가 상승 전후(Day 134~140→142~148): 기여이익률 48.35%→40.82%.
- 세트 도입 전(Day 1~154): 치킨마요 고객의 콜라 구매율 28.23%,
  전체 콜라 구매율 10.43%, 다른 주메뉴 고객의 콜라 구매율 3.37%, Lift 2.71.

## 검증과 한계

기본 seed와 7·19·101·2026, 다른 시작일을 검증했다. 정합성 검사에 더해 기본 데이터의
관계 검사 36개가 통과했고 관측 방향 경고는 없었다.
외래키 손상, 할인 중복 차감, 미래 원가 적용, 세트 구성품 누락, 숨겨진 정답 유입,
Ground Truth 수량 변조와 저장 파일 변조를 검출하는 테스트가 포함된다.

검증기의 `passed`는 정합성과 필수 관계 검사 통과를 뜻한다.
다른 seed에서 관측 가격 구간의 방향이나 매출 증가/이익 감소 데모 방향이 어긋나면
`warnings`에 기록한다. `passed`만 보고 모든 관측 방향이 충족됐다고 해석하면 안 된다.
임의의 모든 seed에 대해 90일 표본의 관계를 보장하는 것은 아니다.

학습 때 Ground Truth와 검증 보고서를 입력에 넣지 않는다. 거래/달력 CSV에서
0건 셀을 포함한 과거 수요를 집계하고, 원가·가격·프로모션은 해당 시점 정보를 조인한다.
시간 순서로 Train/Validation/Test를 나누고 미래 실현 날씨나 미래 판매 집계가 과거에
들어가지 않도록 한다. 기본 시간 분할은 Train 120일, Validation 30일, Test 30일이다.
세트는 Day 155~168에만 있어 효과 학습에는 별도 개입 평가 설계가 필요하다.

현재는 고객 다인 주문, 품절/재고 한도, 경쟁점, 고객별 이질성, 일반 가격 교차탄력성을
생략했다. 주메뉴 외 메뉴의 수요는 조건부 부가구매이며 모든 메뉴의 탄력성을 관측 데이터에서
추정할 수 있는 가격 실험을 제공하지는 않는다. 모델의 확률/구간 정확도는 이후 별도 검증 대상이다.

## 실행 환경에서 확인한 사항

기존 `.venv`는 Python 3.14.7이다. NumPy 가져오기 중 `_umath_linalg` DLL을
Windows 애플리케이션 제어 정책이 차단했고 샌드박스 밖 실행에서도 같은 오류가 발생했다.
환경 보안 설정을 바꾸지 않고 생성·검증에 표준 라이브러리만 사용하도록 결정했다.
Poisson 역누적분포 구현은 표본 평균/분산과 단조 결합을 테스트했으며 셀 평균을 0~100으로 제한한다.
공식적으로 Python 3.14를 지원하는 NumPy 2.4.4 wheel을 임시 설치해 먼저 검증한 뒤
프로젝트 가상환경과 `requirements.txt`를 2.4.4로 맞췄다. Pandas·Matplotlib·SciPy·scikit-learn·
statsmodels 로드, NumPy 선형대수와 PNG 출력을 확인했다. 기존 테스트 19개도 다시 통과했다.
