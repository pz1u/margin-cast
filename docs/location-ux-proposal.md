# 매장 위치·날씨 UI 구조 제안 (H1 준비)

이 문서는 H1 Agent 작업에서 `현재 위치 사용`, `매장 검색`, `실제 기상 예보 반영`을 연결할 때
화면이 가져야 할 **상태와 문구만** 제안한다. 이번 단계에서는 어떤 위치·Kakao·KMA API도
연결하지 않았고, Agent backend 계약도 가정하지 않는다. 아래 상태 이름은 화면 내부 표현이며
API 필드나 응답 형식이 아니다. 실제 연결 때는 H1이 정하는 계약에 맞춰 이 표를 조정한다.

## 현재 구현

- 대시보드의 `매장 위치` 카드는 `위치 기능 준비 중`만 보여준다.
- `web/assets/store-model.js`의 `createLocationState()`는 `NOT_CONFIGURED` 상태와
  `methods.current_location.available = false`, `methods.store_search.available = false`만 가진다.
- 가격 분석은 최근 관측 날씨를 사용하며 화면에도 그렇게 안내한다.

## 상태

| 화면 상태 | 사용자에게 보이는 것 | 다음 행동 |
|---|---|---|
| 위치 없음 | `위치가 설정되지 않았습니다. 날씨는 최근 관측값을 기준으로 합니다.` + [현재 위치 사용] [매장 검색] | 둘 중 하나 선택 |
| 위치 확인 중 | 버튼 비활성, `현재 위치를 확인하고 있어요…`, 취소 링크 | 대기 또는 취소 |
| 현재 위치 권한 거절 | `위치 권한이 꺼져 있어요. 브라우저 설정에서 허용하거나 매장을 검색해 주세요.` | [매장 검색]으로 전환 |
| 위치 확인 실패(시간 초과·기타) | `위치를 확인하지 못했어요. 다시 시도하거나 매장을 검색해 주세요.` + [다시 시도] | 재시도 또는 검색 |
| 매장 검색 중 | 검색 입력, 목록 자리에 `검색하고 있어요…` | 대기 |
| 검색 결과 | 후보 목록(매장명·주소). 결과 없음이면 `검색 결과가 없어요. 다른 이름이나 주소로 찾아 보세요.` | 후보 선택 |
| 위치 선택 완료 | `OO점 · 주소` 요약 + [위치 변경] | 날씨 반영 진행 |
| 날씨 반영 완료 | `실제 단기예보를 반영했어요 (M/D ~ M/D)` 배지, 결과 카드에도 같은 문구 | 그대로 사용 |
| 날씨 반영 불가 | `예보를 가져오지 못해 최근 관측 날씨로 계산했어요.` | 결과에 반드시 표시 |

## 화면 구조 제안

1. 대시보드 `매장 위치` 카드가 위치의 단일 출처다. 위 상태를 이 카드 안에서만 전환한다.
2. 가격 시뮬레이션 폼에는 위치 입력을 두지 않고, 날씨 반영 여부를 한 줄로 보여준다.
   - 위치 없음: `최근 관측 날씨 기준` + [위치 설정하기] (대시보드 카드로 이동)
   - 날씨 반영 완료: `실제 예보 반영 · OO점`
3. 실제 예보는 제공 기간이 짧을 수 있으므로 분석 기간 선택이 제한되면 이유를 문장으로 알려준다.
   (기간 값은 H1 계약이 정한 범위를 따른다.)
4. 결과 카드의 `계산 기준`에 날씨 출처(최근 관측 / 실제 예보)를 항상 표시한다.

## 지켜야 할 원칙

- 권한 거절과 실패는 오류 화면이 아니라 다음 행동이 있는 안내로 보여준다.
- 위치는 사용자가 선택한 뒤에만 요청한다. 페이지 진입 시 자동으로 묻지 않는다.
- 좌표·격자 번호·API 키 등 내부 값은 일반 화면에 표시하지 않는다(`?debug=1`에서만 필요 시).
- 날씨는 수요 문맥이며 메뉴별 날씨 인과효과를 입증하지 않는다는 기존 고지를 유지한다.
- 키보드만으로 검색 입력, 결과 선택, 위치 변경이 가능해야 하고 상태 변화는 `aria-live`로 알린다.
